# Тест-кейсы TestBoard

21 кейс, 11 позитивных и 10 негативных. Каждый кейс выполняется независимо: перед запуском подготавливаются указанные в нём состояние пользователя и данные. Для параметризованных проверок исходные условия восстанавливаются перед каждым вариантом. Имена учётных записей и пароли используются как данные тестового окружения.

## TC-01

**Название:** поиск по слову возвращает релевантную выдачу независимо от регистра.  
**Функционал:** поиск.  
**Вид:** позитивная.  
**Техника:** классы эквивалентности.

**Предусловия:** открыта главная страница TestBoard; пользователь не авторизован. В тестовой ленте есть объявления со словом «пальто» в названии. Набор объявлений не меняется между поисковыми запросами.

**Тестовые данные:** «Пальто», «пАльТо», «ПАЛЬТО».

**Шаги:**
1. Ввести «Пальто» в поле поиска и нажать Enter. Зафиксировать состав выдачи и счётчик результатов.
2. Повторить поиск отдельно для «пАльТо» и «ПАЛЬТО» и сравнить результаты.
3. Прокрутить выдачу вниз до начала подгрузки.

**Ожидаемый результат:** для трёх запросов состав выдачи и счётчик одинаковы. Названия результатов содержат слово «пальто» без учёта регистра. Поле сохраняет именно введённый вариант запроса. Во время подгрузки отображается «Загрузка…».

## TC-03

**Название:** сортировка объявлений по цене.  
**Функционал:** поиск и сортировка.  
**Вид:** позитивная.  
**Техника:** классы эквивалентности.

**Предусловия:** открыта главная страница. Для проверки подготовлена лента из пяти объявлений с указанными ниже ценами; её состав не меняется во время проверки.

**Тестовые данные:** цены 500, 1500, 4000, 5000 и 7000; варианты сортировки «Дешевле» и «Дороже».

**Шаги:**
1. Зафиксировать набор объявлений и счётчик результатов до сортировки.
2. Выбрать «Дешевле». Сравнить цены всех пяти карточек по порядку.
3. Выбрать «Дороже». Повторить сравнение цен.
4. Для каждого варианта сравнить набор объявлений и счётчик с исходными.

**Ожидаемый результат:** «Дешевле» даёт порядок 500, 1500, 4000, 5000, 7000; «Дороже» — обратный. Набор и счётчик объявлений сохраняются. Выбранный пункт отмечен как активный; сообщение об ошибке отсутствует.

2. Открыть карточку.
3. Проверить состав полей по макету и сравнить фотографию с изображением в ленте.

**Ожидаемый результат:** открывается выбранное объявление. Видны название, цена, дата, описание, продавец «Частное лицо», количество и фотография. Фотография соответствует карточке в ленте.

## TC-09

**Название:** ограничение длины описания объявления.  
**Функционал:** новое объявление.  
**Вид:** негативная, с допустимыми контрольными значениями.  
**Техника:** анализ граничных значений.

**Предусловия:** пользователь авторизован. Для каждого варианта открывается новая форма; остальные обязательные поля заполнены корректно, фотография загружена.

**Тестовые данные:** строки из 499, 500 и 501 повторения символа «А»; название «Детская энциклопедия», цена 4000, количество 1, фотография товара.

**Шаги:**
1. В новой подготовленной форме вставить 499 символов в описание и опубликовать объявление. Проверить сохранённую длину описания в карточке.
2. Повторить проверку в новой форме для 500 символов.
3. Открыть новую форму, вставить 501 символ и проверить длину текста в поле. Опубликовать объявление и проверить сохранённую длину.

**Ожидаемый результат:** 499 и 500 символов вводятся и сохраняются полностью. При вставке 501 символа поле содержит 500 символов; 501-й не вводится. Сохраняются 500 символов.

**Допущение:** способ обработки превышения лимита выбран как ограничение ввода. Требование «не более 500 символов» само по себе не определяет этот способ; он требует согласования, см. [открытые вопросы](requirements-notes.md).
